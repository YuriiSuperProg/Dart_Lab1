Ответы на вопросы

1. Чем статическая типизация Dart отличается от Python? Какое практическое преимущество она даёт?

В Python типизация динамическая: тип переменной определяется во время выполнения, и одна и та же переменная может менять тип. В Dart типизация статическая: тип переменной фиксируется на этапе компиляции и не может быть изменён.

Практическое преимущество: компилятор проверяет корректность типов до запуска программы. Ошибки вроде int x = "строка"; или вызова несуществующего метода у типа выявляются сразу, а не в рантайме. Это ускоряет разработку, делает код надёжнее и упрощает рефакторинг.

2. Что означает String?? Чем отличается от String?

String — не-nullable тип: переменная обязана содержать строку и не может быть null.
String? — nullable тип: переменная может содержать либо строку, либо null.
С String? компилятор не позволит напрямую вызвать метод (например, toUpperCase()), пока вы не убедитесь, что значение не null (через if, ?., ! или ??). Это защищает от ошибок NullPointerException.

3. Зачем в Dart final, если в Python можно просто договориться не менять переменную?

final — это гарантия на уровне компилятора, а не устная договорённость. Если переменная объявлена как final, любая попытка присвоить ей новое значение вызовет ошибку компиляции. Это:

защищает от случайного изменения значения;
делает намерения программиста явными для других разработчиков и для анализатора;
позволяет компилятору оптимизировать код.
В Python подобной встроенной гарантии нет — приходится полагаться на соглашения (например, CONSTANT_NAME) и дисциплину.

4. Чем именованный параметр {required String name} отличается от позиционного? Приведите пример вызова.

Позиционный параметр передаётся в порядке объявления:

dart
void greet(String name, int age) { ... }
greet('Артём', 20); // порядок важен
Именованный параметр заключается в {} и передаётся по имени:

dart
void greet({required String name, int age = 0}) { ... }
greet(name: 'Артём', age: 20); // порядок не важен
greet(name: 'Артём');          // age необязателен
Ключевое слово required делает параметр обязательным, даже будучи именованным. Без required параметр опционален и может иметь значение по умолчанию. Именованные параметры повышают читаемость вызова — особенно когда параметров много, что критично во Flutter.
